# MLIR we want to generate

These are handwritten output contracts, not programs already generated by Remora.
They established the target before extending the backend. The ordinary Remora
backend now reaches a generic matmul contraction and runs YOLOv4 through IREE;
its convolution path currently follows the source im2col/matmul implementation.
The direct convolution below remains a target for later recognition. See the
[current backend guide](../mlir.md).

- [Matrix multiplication, bias, ReLU](matmul-bias-relu.mlir)
- [Padded strided convolution, bias, leaky ReLU](conv-bias-leaky.mlir)

Both use ordinary upstream MLIR operations. No new dialect, VeIR dependency, or
opaque runtime kernel is required. Run their full-element CPU checks with:

```sh
python3 scripts/check_mlir_targets.py --mlir-bin-dir /path/to/llvm/build/bin
```

The harness reuses the prototype's MLIR-to-LLVM pipeline and wrapper builder.
It passes tensors into the functions and checks every result element. These two
checks are separate from the compiler-generated execution suite.

## Fusion and window-access experiments

[index-capture.mlir](index-capture.mlir) and [index-input.mlir](index-input.mlir)
show why an explicit index operand enables existing Linalg fusion where a
captured tensor does not. [pool-window.mlir](pool-window.mlir) is an equivalent
13×13 max-pooling target with affine window accesses. Run their checks with
`scripts/check_mlir_fusion.py --tools /path/to/iree/bin` in the validation Python
environment. See the [measured experiments](../../validation/mlir-options-fusion.md).
The window target is handwritten, rather than current compiler output.

## Semantic target

| Block | Contract |
| --- | --- |
| Matmul | `A[M,K] × B[K,N]`, initialized with zero; then add `bias[N]` and apply ReLU. |
| Convolution | NCHW input, FCHW weights, cross-correlation with no kernel flip; explicit zero padding, spatial stride and dilation; then channel bias and leaky ReLU. |

The convolution fixture uses a 3×3 input, two 3×3 filters, padding one, stride two,
and dilation one. Its output is `[1,2,2,2]`. Opposite-signed filters and channel
biases exercise both branches of leaky ReLU. The matmul fixture uses mixed-sign
inputs and exercises both branches of ReLU.

YOLO's CHW tensors would acquire a size-one batch axis at this boundary. Keep its
channel-first layout initially; layout changes should be justified by a target's
performance. Bias alignment is explicit: the convolution epilogue indexes bias
with the output-channel index, while the matrix epilogue uses the column index.
Neither operation changes Remora's prefix frame-agreement rule.

The general spatial output size is
`floor((input + lowPad + highPad - dilation*(kernel-1) - 1)/stride) + 1`.
The compiler must check the shape constraints when it eventually constructs these
operations; producing well-formed types alone does not establish source semantics.

## Why this is a useful target

- Keep contraction structure visible as named operations or equivalent generic
  indexing/reduction maps.
- Use `linalg.generic` for explicit indexing and fused pointwise bias/activation.
- Use zero-initialized destinations for reductions. `tensor.empty` alone does not
  provide the initial accumulator value.
- Supply weights as tensor arguments rather than embedding or expanding them.
- Preserve tensor values until scheduling and bufferization. Emit no memref
  allocation/deallocation decisions from the Remora frontend.
- Keep convolution direct at this stage. MLIR can later choose an im2col/matmul
  implementation; the frontend need not force a large im2col intermediate.
- Keep scalar epilogue arithmetic directly in its region, exposing it to further
  transformations without per-element opaque helper calls.

The fixtures intentionally leave scheduling separate. They contain no tiling,
vectorization, GPU mapping, or claim of competitive YOLO performance. The local
LLVM 22.0.0git bufferization/deallocation pipeline produced:

| Fixture | `memref.alloc` | `memref.copy` |
| --- | ---: | ---: |
| Matmul/bias/ReLU | 2 | 0 |
| Convolution/bias/leaky ReLU | 3 | 1 |

In particular, padding is materialized in this baseline. Tiling/fusion and padding
placement need evaluation before calling the convolution implementation efficient.
These counts describe this pipeline/version, not permanent golden text.

## Source language decisions remain open

The [Halide/IREE/Mojo study](../mlir-study.md) supersedes the earlier proposal to
bootstrap through new source primitives. IREE recognized an equivalent generic
multiply/reduce as matrix-like, so we now have evidence for trying an ordinary
Remora contraction first. Named target operations do not require named source
primitives. The generic fixture and separate row schedule demonstrate these
independent choices.

Preserve explicit access patterns, reduction domains, initialization, and shape
constraints. Any later recognition rule or primitive can use the same target
lowering. Source primitives remain an optional response to an observed problem.
